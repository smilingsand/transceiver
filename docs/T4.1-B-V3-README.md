# T4.1-B V3 — Windows Bridge Lab Controller

## Design

- Continue using the existing V2 PID + process creation-time + command-line protections. `stop` never kills generic `node.exe` or other unmanaged processes.
- Start Bridge and tunnel-client with hidden windows and separate stdout/stderr files in `D:\AI-Brain\BridgeLab\logs`.
- Use the previously verified Codex Desktop-managed CLI at `%LOCALAPPDATA%\OpenAI\Codex\bin\22cfb1d302613eae\codex.exe`, **not PATH**; require exact `codex-cli 0.166.0-alpha.5.1` by default. An explicit `-CodexBin` and `-ExpectedCodexVersion` override is available for *manually tested* upgrades. No scanning or auto-picking newest hashes.
- Read `OpenAI_Tunnel_API_KEY` and `Tunnel_ID` from process or Windows user environment; pass them to tunnel client as `CONTROL_PLANE_API_KEY` and `CONTROL_PLANE_TUNNEL_ID` without writing values to files.
- Existing configuration, SQLite state, and tunnel profiles stay unchanged. `status` distinguishes stopped from unmanaged Bridge listeners.

## Important trade-offs

An unstarted Desktop cannot provide a live CLI process path. The known-good pin is deterministic even when Desktop is closed, but must be reviewed after Desktop updates; do not delete any Desktop-managed `codex.exe`. `-CodexBin` is a directory, not an executable path.

`status` saying `Tunnel managed: True` proves process identity/liveness, **not cloud tunnel connectivity**. Check tunnel logs and actually call an MCP tool after startup.

The existing implementation stores PID metadata in `control/processes.json`; it does not save secrets. Standard output/error redirection writes ordinary process logs: do not assume upstream software will never log sensitive information, so restrict log access and avoid publishing logs unredacted.

## Install and test

1. Confirm existing services are stopped and copy `scripts/bridge-lab.ps1` over the prior version in `D:\MyWorks\transceiver\scripts` (keep a backup).
2. Run the PowerShell syntax check:
   ```powershell
   $t=$null; $e=$null; [System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path .\scripts\bridge-lab.ps1).Path,[ref]$t,[ref]$e)|Out-Null; $e
   ```
3. `./scripts/bridge-lab.ps1 -Action status`
4. `./scripts/bridge-lab.ps1 -Action start`
5. `./scripts/bridge-lab.ps1 -Action status` and verify through ChatGPT that an MCP read tool works.
6. `./scripts/bridge-lab.ps1 -Action stop`, then `status`.
7. Restart if you want services left running. Do **not** commit until Windows tests succeed.

For validated upgrades:
```powershell
.\scripts\bridge-lab.ps1 -Action start -CodexBin 'C:\path\to\tested\hash' -ExpectedCodexVersion '0.xxx.x'
```

## Known limitations / follow-ups

- Windows PowerShell and actual Windows 10 runtime have not yet been verified for this V3; all status/start/stop claims await testing.
- The current code includes a simple two-second tunnel startup check, not a control-plane handshake check.
- The existing V2 `stop` only checks managed process identity and then removes the PID file; it is not a full process-tree / graceful-shutdown manager.
- Desktop updates may replace the pinned CLI; change only after compatibility validation.
