# T4.4-E Windows Controller — start 自恢复优化

这份完整脚本基于用户提供的 `scripts/bridge-lab.ps1` 修改。**尚未在 Windows PowerShell 5.1 执行实测**，请先备份并验证，再覆盖当前脚本；不要直接替换正在运行的 Controller 而不备份。

## 预期行为

- Bridge 和 Tunnel 都健康、受 Controller 管理：`start` 幂等，不重启，PID 不变。
- Bridge 运行、Tunnel 已退出：只恢复 Tunnel，Bridge PID 不变。
- Tunnel 运行、Bridge 已退出：只恢复 Bridge，Tunnel PID 不变。
- 两者已退出但旧 PID 记录存在：在没有未知端口监听或非托管 Tunnel 时启动两个组件，并写入新记录。
- 未管理的进程占用 Bridge 端口，或存在非托管 tunnel-client：拒绝启动，不接管也不终止未知进程。
- Bridge 进程存活但不健康：拒绝自动终止，要求人工排查。
- 任一启动失败：只回滚本次启动的新进程，保留此前已有受管进程及记录。

> 注意：Tunnel 进程存活不代表云端连接已真正可用；现有 Controller 只有 Bridge `/healthz` 检测和 Tunnel 存活判断。此版本尚未增加 Tunnel 上游连接健康检查，也不包含跨进程锁，不建议并发调用多个 `start`。

## 本地步骤（单行 PowerShell 命令）

从下载位置取得 `bridge-lab-T4.4-E.ps1`，先备份原文件：

```powershell
Copy-Item 'D:\MyWorks\transceiver\scripts\bridge-lab.ps1' 'D:\MyWorks\transceiver\scripts\bridge-lab.ps1.T4.4-E-backup' -Force
```

先在新脚本所在目录做语法解析检查（下面用 Downloads 目录举例，替换成真实路径）：

```powershell
$tokens=$null; $errors=$null; [System.Management.Automation.Language.Parser]::ParseFile('D:\Downloads\bridge-lab-T4.4-E.ps1',[ref]$tokens,[ref]$errors) | Out-Null; $errors | Format-List
```

无错误后复制覆盖（替换源路径为实际下载位置）：

```powershell
Copy-Item 'D:\Downloads\bridge-lab-T4.4-E.ps1' 'D:\MyWorks\transceiver\scripts\bridge-lab.ps1' -Force
```

## 验收顺序

在 `D:\MyWorks\transceiver` PowerShell 中，确保 CODEX_MCP_BRIDGE_* 配置正确。每步先检查输出，不要一下子批量执行。全部为单行命令。

1. 查看当前：` .\scripts\bridge-lab.ps1 -Action status `
2. 两组件都运行时启动：` .\scripts\bridge-lab.ps1 -Action start `；确认 PID 均不变。
3. 使用 `Get-CimInstance Win32_Process -Filter "Name='tunnel-client.exe'" | Select-Object ProcessId,CommandLine` 查出受管 Tunnel PID，并和状态核对；仅在确认身份后停止测试 Tunnel。
4. 停掉受管 Tunnel 后执行 ` .\scripts\bridge-lab.ps1 -Action start `；确认 Bridge PID 保持，Tunnel 新 PID 出现。
5. 使用 MCP `codex_settings` / `codex_status` / `git_status` 验证远端连接与历史状态。
6. 在合适的空闲窗口测试 Bridge 单独退出的恢复逻辑，避免打断运行中的 Codex 任务。
7. 最后运行 `git diff --check`、`git diff -- scripts/bridge-lab.ps1`，审核后再 Git commit。

### 风险与回滚

如果发现异常，先不要强制重启未知进程。原文件备份已保留；回滚命令：

```powershell

```
